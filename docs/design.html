기념식 프롬프터 재설계
Design Spec · 창립 42주년 기념식 사회자 프롬프터

페이지 넘김이 아닌, 흐르는 프롬프터로 재설계

후배 버전(v1)을 분석하고 외부 프롬프터 앱·방송용 프롬프터 소프트웨어 기능을 벤치마킹한 뒤, 대사 표시와 연속 스크롤에 집중한 v2 설계안을 정리함. 구현은 아직 안 함. 마지막 장의 결정 사항만 정해주면 바로 제작 들어감.

대사 79개본문 4,246자식순 8개영상 큐 14개순발화 약 13분출연 MC 2명 + 상장 낭독
00 · 결론 먼저

한 줄 진단과 방향

진단. v1은 「대사 편집기 + 한 장씩 넘기는 뷰어」에 가까움. 시선 표기·편집·되돌리기·수정본 저장 같은 부가 기능이 촬영 화면에 상주하고, 정작 프롬프터의 본질인 일정 속도로 부드럽게 흐르는 대사와 운영자의 즉각적 속도·정지 제어가 없음.

방향. ① 촬영 모드와 편집 모드를 분리 ② 픽셀 단위 연속 스크롤 엔진(rAF) 도입 ③ 시선 필드 제거 ④ 영상 송출 큐 지점에서 자동 정지(Hold) ⑤ 운영자 UI는 TV 화면에서 자동으로 사라짐. 기존 대본 JSON 구조와 화자 색상은 그대로 계승.

부드러운 스크롤 구현 관행

  • setTimeout + 1px 스텝 방식은 60/120Hz 화면에서 스터터. 브라우저 타이머 클램프(약 4ms)에도 걸림.
  • 권장: requestAnimationFrame + 프레임 간 경과시간(Δt) 기반 px/s 계산 + 부동소수 서브픽셀 누산. 내부 위치는 float로 유지해 저속에서 「멈춘 것처럼 보이는」 현상 제거.
  • 속도 변경은 즉시 점프가 아닌 가속도 적용(Imaginary acceleration 1.45).
  • WPM은 참고 지표. 실제 제어는 상대 속도 단계라는 견해가 일반적(Power Prompter는 % · words/s · WPM · lines/s 단위를 클릭으로 전환).

04 · 설계 원칙

v2가 지킬 다섯 가지

1. 대사가 왕

화면 면적의 90% 이상을 대사에 씀. 화자·큐·식순은 대사를 방해하지 않는 크기와 색으로 물러남.

2. 흐름 우선

픽셀 단위 연속 스크롤. 속도는 키 한 번에 즉시 바뀌고, 정지·재개도 한 키. 어떤 이동도 덜컥이지 않음.

3. 큐에서 멈춤

영상·CG 송출 큐가 읽기선에 닿으면 자동 정지(Hold). 운영자가 재개할 때까지 대기. 14개 대기 구간을 사람이 일일이 잡지 않아도 됨.

4. 촬영 중 편집 금지

촬영 모드에서는 어떤 클릭도 글을 바꾸지 못함. 대사 수정은 별도 편집 모드에서만.

5. 운영 UI는 보이지 않게

운영자 컨트롤은 마우스가 움직일 때만 나타나고 3초 뒤 사라짐. TV에는 대사만 남음.

06 · 스크롤 엔진

부드럽게, 즉시 반응하게

구동 방식

  • requestAnimationFrame 루프에서 y += 속도(px/s) × Δt. 프레임 드랍이 있어도 시간 기준이라 속도가 일정.
  • 브라우저 scrollTo가 아니라 대본 컨테이너에 transform: translate3d(0,-y,0). 내부 위치는 부동소수로 누산해 저속에서도 끊기지 않고, GPU 합성으로 떨림 없음.
  • 정지·재개·속도 변경은 300ms 이징으로 가감속. 텍스트가 덜컥 멈추거나 튀지 않음.
  • 단위는 내부적으로 vh/s. TV가 1080p든 4K든 같은 체감 속도.

이동 동작

  • 넛지 한 줄(줄높이) 단위 위·아래 미세 이동, 250ms 이징. 마우스 휠은 게인(기본 2.0) 설정으로 감도 조절.
  • 대사 점프 이전·다음 대사의 첫 줄을 읽기선에 맞춰 400ms 이징 스크롤. v1의 「넘김」은 이 부드러운 형태로만 남김.
  • 식순 점프 드롭다운 또는 숫자키. 점프 후에는 자동 정지 상태로 대기.
  • Hold HOLD 큐 요소의 상단이 읽기선에 닿으면 자동 정지 + 배지 점멸. Space로 재개.
  • 여기부터 정지 상태에서 대사를 클릭하면 그 대사 첫 줄을 읽기선에 맞춤(Prompt From Here). 촬영 모드에서 클릭은 편집이 아닌 위치 지정.
  • 끝 도달 마지막 대사 뒤 여백에서 자동 정지. 「대본 끝」 표시.

07 · 타이포·가시성

3m 거리에서 읽히는 글자

글자 크기 계산

기준
편안한 판독 글자 높이 ≥ 시거리 ÷ 120 (방송·사이니지 관용 기준)
3m
글자 높이 25mm 이상
55인치 1080p
픽셀 피치 0.63mm → 25mm ≈ 40px 글자 높이
한글 폰트
글자 높이 ≈ em의 0.85 → 최소 font-size 약 47px
여유 1.6배
약 75px = 7vh. v1의 76px은 적정. 4m 이상이면 9vh.
화면 표시 줄수
7vh × 줄높이 1.45 ≈ 10.2vh/줄 → 약 9줄. 읽기선 위 3줄, 아래 6줄. 뉴스 프롬프터 관행 5~8줄과 부합.

서체·색

  • 서체: 시스템 고딕(Apple SD Gothic Neo / Malgun Gothic / Noto Sans CJK KR). 단일 파일·오프라인 조건상 웹폰트 미사용.
  • 굵기 700. v1의 800은 획이 붙어 3m에서 뭉침. 자간 −0.01em, word-break: keep-all로 단어 중간 줄바꿈 방지.
  • 한 줄 최대 20~24자. 폭이 넓으면 눈이 좌우로 움직여 카메라 시선이 흔들림. 본문 폭 기본 86%.
  • 배경 순검정 #000, 대사 #F4F6F8(순백 대비 눈부심 저감). 지나간 대사 36%.
  • 화자 색은 v1 계승: 김우중 스카이블루, 최윤정 핑크, 상장 낭독 골드. 색은 바·이름표에만, 본문은 흰색 고정.
  • 상장 낭독은 원문 줄바꿈 유지, 가운데 정렬, 골드 이름표. 읽는 속도가 느려지므로 해당 블록 진입 시 속도 −1 자동 적용 옵션.

09 · 모드·데이터·파일

촬영 모드와 편집 모드의 분리

촬영 모드 (기본)

  • 텍스트 선택·편집 불가. 우클릭 메뉴 차단. 커서 자동 숨김.
  • 설정(속도·글자·폭·미러·클리커 모드)은 localStorage에 저장.
  • 진행 위치는 저장하지 않음. 열 때마다 처음부터. 대신 「마지막 위치로」 버튼 1개.
  • 화면 잠김 방지: Wake Lock API로 촬영 중 TV 절전·화면보호기 진입 차단.

편집 모드 (E키 · 확인 후)

  • 대사 텍스트 수정, 큐의 HOLD 여부 토글, 대사 순서는 고정.
  • 수정본은 v1처럼 HTML로 내려받기. 원문 해시로 어느 대본에서 파생됐는지 표기.
  • 되돌리기·다시 실행은 편집 모드 안에서만 활성.
  • 편집 화면은 밝은 배경의 목록형. 촬영 화면과 시각적으로 완전히 다르게 해 지금 어느 모드인지 착각하지 않게.

데이터 스키마 (v1 계승 + 확장)

items[]        id · speaker · kind(dialogue|award) · section · text · before[]
before[]       kind(heading|cue) · text · hold:boolean   ← 신규. 「송출」 포함 큐는 기본 true
headings[]     index · text                             ← 식순 점프·진행 바 마커
settings       speedLevel · fontVh · widthPct · mirror · guidePct · clickerMode · fadePast · autoHold
gaze           읽기만 하고 화면에 표시하지 않음 (스키마 호환 유지)

선택 사양: 운영자 창 분리

같은 노트북에서 TV를 확장 화면으로 쓸 때, 운영자 창(노트북)과 출연자 창(TV)을 BroadcastChannel로 동기화. 운영자 창에는 전체 대본 목록·속도·타이머·다음 큐가 항상 보이고, TV에는 대사만 남음. 11장 결정 사항 A에 해당.
